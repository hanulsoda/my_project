# 학습 플레이어를 DS918+에 올리기

학원 사이트에 로그인한 학생만 집에서도 학습 플레이어를 쓸 수 있게 DS918+에 설치하는 순서입니다. 메뉴 이름은 DSM 7.2 기준이며 버전에 따라 조금 다를 수 있습니다.

**준비물:** DS918+ 관리자 계정, 공유기 관리 화면, 학원 도메인 관리(DNS) 화면, 학원 사이트 파일을 고칠 권한, Claude API 키, 윈도우 PC

**주의:** 5단계에서 공유기 설정을 바꾸는 순간 DS718+의 기존 영상 주소는 바깥에서 열리지 않습니다. 5단계와 6단계(학원 사이트 버튼 교체)는 같은 날 이어서 하세요.

## 1. DS918+에 영상이 다 있는지 확인 (윈도우 PC)

1. 파일 탐색기 주소창에 `\\DS718주소`, `\\DS918주소`를 넣어 두 시놀로지의 영상 공유 폴더가 열리는지 확인합니다. 예: `\\192.168.0.10`
2. 명령 프롬프트에서 아래를 실행합니다. 공유 폴더 이름이 `video`가 아니면 바꿔 넣으세요. **`/L` 때문에 목록만 보여 주고 아무것도 복사하지 않습니다.**
   ```bat
   robocopy "\\DS718주소\video" "\\DS918주소\video" /E /L /NJH /NJS /NDL /XD "#recycle" "@eaDir"
   ```
   나오는 파일이 DS918+에 없거나 다른 파일입니다. 아무것도 안 나오면 다 있는 것입니다.
3. 파일이 나왔다면 `/L`만 빼고 같은 명령을 다시 실행해 복사합니다. 복사만 하고 지우지는 않습니다. **`/MIR`는 쓰지 마세요.** DS918+에만 있는 파일을 지웁니다.

## 2. 비밀 키 만들기

입장 링크에 쓸 비밀 키를 만듭니다. 플레이어(3단계)와 학원 사이트(6단계) 두 곳에 **같은 값**을 넣습니다.

```bat
python -c "import secrets; print(secrets.token_hex(32))"
```

64자짜리 값이 나옵니다. 남에게 보여 주거나 GitHub에 올리지 마세요.

## 3. 플레이어 파일 준비

1. https://github.com/hanulsoda/my_project 에서 브랜치 `claude/epic-dijkstra-0evz2k`(나중에 main으로 합쳐지면 main)를 고르고 **Code > Download ZIP**으로 받아 압축을 풉니다.
2. 제어판 > **공유 폴더** > **생성**으로 `study-data` 공유 폴더를 만듭니다. 분석 결과가 저장될 곳입니다. 비밀 키가 든 `docker` 폴더와 따로 두어서, 7단계에서 Z840에 이 폴더만 열어 줄 수 있게 합니다. **4단계(Container Manager로 실행)보다 먼저 만들어야 합니다.** 없으면 Docker가 공유 폴더가 아닌 보통 폴더로 만들어 버립니다.
3. 메모장으로 `docker-compose.yml`을 열어 채웁니다.
   - `/volume1/video` → DS918+의 강의 영상 폴더 경로. File Station에서 폴더를 마우스 오른쪽 버튼 > 속성 > 위치에서 볼 수 있습니다.
   - `/volume1/study-data` → 2번에서 만든 폴더 경로. 대개 그대로 두면 됩니다.
   - `ENTRY_SECRET` → 2단계의 비밀 키
   - `SITE_URL` → 학원 사이트 주소. `https://`로 시작해야 합니다(막힘 화면에 링크로 나옵니다)
   - `ANTHROPIC_API_KEY` → Claude API 키
4. **사용 한도 정하기:** [Claude Console](https://platform.claude.com/)에서 **Spend limits(사용 한도)**를 찾아 한 달 한도를 정합니다. Settings > Limits나 Billing 화면에 있습니다. 질문하기는 횟수 제한이 있지만, 한도를 정해 두면 키가 새거나 예상보다 많이 써도 그 금액에서 멈춥니다. 한도에 닿으면 다음 달 1일 오전 9시(한국 시간)까지 질문하기와 분석이 멈추고, 영상 시청은 계속됩니다.
5. DS918+의 **패키지 센터**에서 **Container Manager**를 설치합니다. `docker` 공유 폴더가 생깁니다.
6. File Station에서 `docker` 폴더 안에 `study-player` 폴더를 만들고, 압축을 푼 내용물을 그 안에 올립니다. `docker-compose.yml`이 `docker/study-player` 바로 아래에 있어야 합니다.

## 4. Container Manager로 실행

1. Container Manager > **프로젝트** > **생성**
2. 프로젝트 이름 `study-player`, 경로 `/docker/study-player`. 경로에 있는 `docker-compose.yml`을 사용합니다. 웹 포털(Web Station) 설정은 건너뜁니다.
3. 완료하면 이미지를 만들고 실행합니다. 처음에는 몇 분 걸립니다.
4. **확인:** Container Manager > **컨테이너**에서 `study-player`로 시작하는 컨테이너가 **실행 중**이고, 눌러서 **로그**에 `Uvicorn running on http://0.0.0.0:8000`이 보이면 정상입니다.
   - 학원 PC에서 `http://DS918주소:8000`은 **열리지 않는 것이 정상**입니다. 내부망에서 https를 건너뛰고 들어오는 길을 막아 두었고, 5단계의 인터넷 주소로만 들어옵니다.
   - 컨테이너가 바로 꺼지면 로그에 `ENTRY_SECRET(입장 링크 비밀 키)가 없거나…`가 있는지 보세요. 비밀 키를 빠뜨린 것입니다.

## 5. 인터넷 주소 연결

1. **DNS:** 도메인 관리 화면에서 `study` 레코드를 추가합니다. 값은 지금 DS718+ 영상 주소가 가리키는 것과 같은 학원 인터넷 주소(공인 IP)입니다.
2. **공유기:** 포트 포워딩에서 **80, 443번**이 DS718+ 대신 **DS918+의 내부 주소**로 가도록 바꿉니다.
3. **인증서:** 제어판 > **보안** > **인증서** > **추가** > 새 인증서 추가 > **Let's Encrypt에서 인증서 받기**
   - 도메인 이름 `study.학원도메인`, 이메일 입력 > 완료
   - 80번 포트가 DS918+로 열려 있어야 발급되고, 90일마다 자동으로 갱신됩니다.
4. **역방향 프록시:** 제어판 > **로그인 포털** > **고급** > **역방향 프록시** > **생성**
   - 소스: 프로토콜 `HTTPS`, 호스트 이름 `study.학원도메인`, 포트 `443`, **HSTS 사용** 체크
   - 대상: 프로토콜 `HTTP`, 호스트 이름 `127.0.0.1`, 포트 `8000`
   - **사용자 지정 머리글** > 생성 > 이름 `X-Forwarded-Proto`, 값 `$scheme` (통과 쿠키를 https에서만 쓰게 합니다)
5. 제어판 > 보안 > 인증서 > **설정**에서 `study.학원도메인` 항목에 3번의 인증서를 고릅니다.
6. **확인:** 휴대폰의 와이파이를 끄고(데이터로) `https://study.학원도메인` 을 엽니다. 자물쇠 표시와 함께 "학원 사이트에 로그인한 뒤 들어와 주세요"가 나오면 정상입니다.

## 6. 학원 사이트에 "강의 보기" 버튼 달기

입장 링크는 5분만 유효합니다. 학생이 화면을 오래 열어 둔 뒤 눌러도 되도록, 버튼은 **누르는 순간 새 링크를 만드는 페이지**로 연결합니다.

1. 저장소의 `deploy/study_player_link.php`를 학원 사이트에 올립니다.
2. 비밀 키는 **웹 주소로 열리지 않는 폴더**에 둡니다. 보통 `www`나 `public_html` 폴더의 바로 위입니다. 그곳에 아래 한 줄로 `study_secret.php`를 만듭니다.
   ```php
   <?php return '2단계의 비밀 키';
   ```
   웹 폴더 안에 두면 사이트 백업 파일이나 서버 설정 실수로 키가 샐 수 있습니다.
3. 1번과 같은 폴더에 아래 내용으로 `study_go.php`를 만듭니다.
   ```php
   <?php
   // "강의 보기" 버튼이 오는 페이지. 누른 순간의 새 입장 링크로 보냅니다.
   session_start();
   // ↓ 다른 학생 전용 페이지와 똑같은 로그인 확인으로 바꾸세요.
   //   바꾸지 않으면 아무도 들어갈 수 없습니다(실수해도 열리지 않게 한 기본값).
   if (empty($_SESSION['여기에_로그인_확인_키'])) {
       http_response_code(403);
       exit('로그인이 필요합니다.');
   }
   require_once __DIR__ . '/study_player_link.php';
   $secret = require __DIR__ . '/../study_secret.php';  // 2번의 파일. 위치가 다르면 경로를 맞추세요
   header('Location: ' . study_player_link('https://study.학원도메인', $secret));
   ```
4. 로그인한 학생이 보는 화면의 기존 DS718+ 영상 링크를 `<a href="study_go.php">강의 보기</a>`로 바꿉니다. 폴더가 다르면 경로를 맞추세요.
5. **확인:** 학생 계정으로 로그인 > 강의 보기 > 강의 목록이 나오면 정상입니다. 로그아웃한 상태에서 `study_go.php`를 직접 열면 "로그인이 필요합니다."가 나와야 합니다.

## 7. Z840에서 분석하고 결과를 DS918+에 저장

플레이어가 읽는 영상 폴더와 같은 폴더를 분석해야 강의와 요점 정리가 짝지어집니다.

1. **Z840 전용 시놀로지 계정:** 제어판 > **사용자 및 그룹** > **생성**으로 `z840` 계정을 만듭니다.
   - 공유 폴더 권한: `study-data`는 **읽기/쓰기**, 영상 폴더(`video`)는 **읽기 전용**, `docker`를 포함한 나머지는 **액세스 없음**. `docker` 폴더의 `docker-compose.yml`에 든 비밀 키와 API 키를 Z840에서 볼 수 없게 하기 위해서입니다.
   - 응용 프로그램 권한: **SMB**만 허용하고 나머지는 거부합니다.
2. Z840에서 아래를 실행합니다.

```bash
# 처음 한 번만: 분석 프로그램 받기 (8단계의 git pull로 새 버전을 받으려면 ZIP 대신 이렇게 받습니다)
sudo apt install git cifs-utils python3-venv
cd ~ && git clone -b claude/epic-dijkstra-0evz2k https://github.com/hanulsoda/my_project
cd ~/my_project && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

sudo mkdir -p /mnt/video /mnt/study-data
sudo mount -t cifs //DS918주소/video /mnt/video -o username=z840,ro,uid=$(id -u)
sudo mount -t cifs //DS918주소/study-data /mnt/study-data -o username=z840,uid=$(id -u)
cd ~/my_project && source .venv/bin/activate
# 처음 한 번만: Claude API 키를 파일에 저장 (입력한 키는 화면에 보이지 않음)
read -s -p "Claude API 키: " k && echo "$k" > ~/.anthropic_key && chmod 600 ~/.anthropic_key && unset k
VIDEO_DIR=/mnt/video DATA_DIR=/mnt/study-data ANTHROPIC_API_KEY=$(cat ~/.anthropic_key) python -m academy.analyze
```

비밀번호를 물으면 1번에서 만든 `z840` 계정의 비밀번호를 넣습니다. 분석이 끝난 강의부터 학생 화면에 요점 정리가 나타납니다. 플레이어를 다시 시작할 필요는 없습니다. GPU 설정은 README의 "NVIDIA GPU 쓰기"를 보세요.

## 8. 새 버전으로 바꾸기

새 기능이 생기면 DS918+의 플레이어와 Z840의 분석 프로그램을 각각 바꿉니다. 학생 메모·이어보기(학생 브라우저에 저장)와 분석 결과(`study-data` 공유 폴더)는 그대로 남습니다.

**DS918+ (학생이 보는 플레이어)**

1. 3단계처럼 새 ZIP을 받아 압축을 풉니다.
2. File Station에서 `docker/study-player` 안의 **`academy` 폴더를 먼저 지운 뒤** 새 `academy` 폴더를 올립니다. (덮어쓰기는 폴더를 합치기만 해서 예전 파일이 남습니다.) `Dockerfile`, `requirements-server.txt`는 새 것으로 덮어씁니다.
3. **`docker-compose.yml`은 덮어쓰지 마세요.** 비밀 키가 들어 있습니다. 대신 새 `docker-compose.yml`을 메모장으로 열어, 지금 것에 없는 줄이 생겼으면 그 줄만 옮겨 적습니다.
4. Container Manager > **프로젝트** > `study-player` > **작업** > **빌드**. 새 이미지를 만든 뒤 다시 실행합니다. 빌드 뒤에도 예전 그대로면 **중지** → **정리** → **빌드** 순서로 한 번 더 합니다.
5. **확인:** 학원 사이트에서 "강의 보기"로 들어가 새 기능(예: 강의 목록 위 검색칸)이 보이면 됩니다. 예전 화면이 그대로면 브라우저에서 Ctrl+F5로 새로 고칩니다.
6. 빌드할 때마다 예전 이미지(약 250MB)가 남습니다. 가끔 Container Manager > **이미지**에서 쓰지 않는 이미지를 지웁니다.

**Z840 (분석)**

```bash
cd ~/my_project && git pull && source .venv/bin/activate && pip install -r requirements.txt
```

- `fatal: not a git repository`가 나오면 예전에 ZIP으로 받아 둔 것입니다. `mv ~/my_project ~/my_project-old`로 이름을 바꿔 두고 7단계의 "처음 한 번만" 두 줄부터 다시 합니다(`.venv`도 새로 만들어집니다).
- 브랜치가 나중에 main으로 합쳐져 `git pull`이 브랜치를 못 찾는다고 하면 `git checkout main && git pull`로 바꿉니다.
- `pip install`을 빠뜨리면 새로 필요한 라이브러리가 없어서 분석이 받아쓰기 전에 멈추고 설치하라고 알려 줍니다. 이미 분석한 영상에 새 기능(예: 판서 사진)을 넣으려면 README의 "3. 영상 분석"을 보세요.

## 막힐 때

| 증상 | 확인할 것 |
| --- | --- |
| 모든 학생이 "로그인한 뒤 들어와 주세요"에서 막힘 | 3단계와 6단계의 비밀 키가 같은지, DS918+와 웹호스팅 서버의 시계가 맞는지(5분 넘게 차이 나면 링크가 바로 만료됨) |
| 컨테이너가 켜지자마자 꺼짐 | 로그의 비밀 키 메시지. `ENTRY_SECRET`은 32자 이상. `SITE_URL`은 `https://`로 시작 |
| 강의 목록이 비어 있음 | `docker-compose.yml`의 영상 폴더 경로. 바꾼 뒤 프로젝트를 다시 빌드 |
| 바깥에서 주소가 안 열림 | DNS의 `study` 레코드, 공유기 80·443 → DS918+, 역방향 프록시 규칙 |
| `502 Bad Gateway` 같은 오류 화면 | 4단계처럼 컨테이너가 실행 중인지, 역방향 프록시 대상이 `127.0.0.1`·`8000`인지 |
| 학원 안에서만 주소가 안 열림 | 공유기가 내부에서 자기 공인 IP로 들어가는 기능(NAT 루프백)을 지원하는지. 안 되면 공유기 관리 화면에서 켜거나 휴대폰 데이터로 확인 |
| 인증서 발급 실패 | 공유기 80번이 DS918+로 가는지 |
| 질문하기가 "AI 답변을 받지 못했습니다" | Container Manager > **컨테이너** > `study-player` > **로그**에서 `AI 답변 실패` 아래 줄. 학생 화면에는 원인을 보이지 않습니다. 대개 `ANTHROPIC_API_KEY`가 비었거나 틀린 것입니다 |
| Z840에서 분석 결과를 저장할 때 권한 오류 | 제어판 > 공유 폴더 > `study-data` > 편집 > 권한에서 `z840` 계정이 읽기/쓰기인지 |
| Z840에서 `mount`가 `Permission denied` | 7단계 1번의 `z840` 계정에 SMB가 허용됐는지, 공유 폴더 이름과 비밀번호 |
| 새 버전으로 바꿨는데 화면이 그대로 | 8단계에서 프로젝트를 다시 **빌드**했는지(다시 시작만 하면 예전 이미지로 실행됨), 브라우저 Ctrl+F5 |
| 검색에서 어떤 강의만 안 나옴 | 그 강의의 분석 파일을 손으로 고치다 형식이 틀렸을 수 있습니다. Container Manager 로그에 `검색에서 건너뛴 분석 파일`과 파일 이름이 남습니다 |
