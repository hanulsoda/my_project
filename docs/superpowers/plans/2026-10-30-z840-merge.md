# z840-player 기준으로 합치기 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** z840-player를 이 브랜치의 바탕으로 삼고, 학원 사이트 입장 확인(내부망은 그대로 열림)·요청 크기 제한·질문하기 보호·페이지 찾기 고침·인터넷 공개 안내서를 옮겨 심는다.

**Architecture:** `origin/claude/z840-player`를 merge하고 공통 파일은 저쪽 판을 쓴다. 그 위에 `academy/server.py`의 `create_app`에 키워드 인자 `entry_secret`, `site_url`과 미들웨어 두 개(입장 확인, 요청 크기)를 더하고, 질문하기 경로에 제한을 넣는다. 인터넷 요청은 DS918+ 역방향 프록시를 거쳐 Z840의 기존 서버로 온다.

**Tech Stack:** Python 3.13(venv), FastAPI/Starlette, PyAV<19, numpy, pytest, PHP(학원 사이트)

**Spec:** `docs/superpowers/specs/2026-10-30-z840-merge-design.md`

## Global Constraints

- 화면 글·주석·문서는 한국어. 공개 저장소에 강의 내용·분석 결과·비밀 키·실제 도메인을 올리지 않는다.
- `ENTRY_SECRET`이 없으면 z840-player와 동작이 같아야 한다(저쪽 테스트가 그대로 통과).
- 커밋 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`와 `Claude-Session: https://claude.ai/code/session_01E9tfdKEy34q2Brc6saoVqt`. 푸시는 `claude/epic-dijkstra-0evz2k`에만.
- 저쪽 결정은 바꾸지 않는다: 대본 숨김, 질문하기 끔(`create_app(..., None, ...)`), 화면 구성.

## Review Focus

1. DS918+ 프록시가 `X-Forwarded-For`를 안 붙이면 인터넷 요청이 DS918+의 사설 주소로 보여 문이 열린다. `X-Forwarded-Proto`만 있는 요청은 밖으로 본다(Task 2 테스트). 그래도 안내서의 "휴대폰 데이터로 열어 보기" 확인이 마지막 그물이다(Task 5).
2. 집(인터넷, 통과 쿠키)에서 만든 기기 옮기기 코드를 학원 내부망에서 받는다. 같은 서버 메모리라 되어야 한다(Task 2 테스트).
3. 기기 옮기기 1.5MB가 요청 크기 제한에 걸리면 안 된다(Task 3 테스트).
4. 프록시 뒤에서 uvicorn에 `--proxy-headers`를 안 줘도 `X-Forwarded-Proto: https`면 통과 쿠키에 Secure가 붙는다(Task 2 테스트).
5. 회전 정보만 붙은 세로 휴대폰 영상의 페이지 그림이 누워 나오면 안 된다(Task 4 테스트, ffmpeg 있을 때).
