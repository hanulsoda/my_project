# 교사용 PDF → 요점노트·시험대비문제 → 강의 영상 연결 (설계)

## 왜 하는가
학원은 미래엔 교사용 PDF(단원별로 잘라 둔 것)를 갖고 있다. 이것으로 요점 정리와 시험대비문제를 만들고,
학생이 해당 강의 영상을 보다가 **영상 아래에서 바로 요점노트를 읽고 문제를 풀 수 있게** 한다.
교사는 같은 내용을 PDF로 받아 드라이브에서 검토·인쇄한다.

## 목표 / 비목표 / 하면 안 되는 것
- 목표
  - 드라이브 `수업용 > 2022년 개정` 폴더의 나머지 15개 단원 PDF(총 18개에서 이미 만든 4-2, 5-1과 `부록.pdf`를 뺀 것. 그중 4-1은 파일이 커서 읽기 확인이 필요)에 같은 방식으로 요점노트·시험대비문제를 만든다.
  - 영상 이름이 단원 번호, 단원 제목, 작품명 등 제각각이어도 알맞은 영상에 자동으로 연결한다.
  - 학생은 플레이어에서 요점노트를 보고, 문제를 풀고 바로 채점·해설을 본다.
- 비목표(이번에 하지 않는다)
  - 틀린 문제 복습 화면(`review.html`)과 선생님 현황 통계에 새 문제를 넣기.
  - 플레이어에서 PDF를 내려받기·인쇄하기(PDF는 선생님용으로 드라이브에만 둔다).
  - 학생 답안 서버 저장, 서술형 자동 채점.
- 하면 안 되는 것(실패로 본다)
  - 엉뚱한 영상에 다른 단원의 문제가 붙는 것(연결하지 않는 편이 낫다).
  - 검수 전인 AI 문제가 학생에게 보이는 것.
  - 교재 지문 원문이 공개 저장소나 공개 인터넷에 노출되는 것.

## 이미 있는 것 (코드로 확인함)
- 영상 파일 이름에 작품명이 들어 있으면 `REFERENCES_FILE`의 학원 정리를 자동으로 붙이는 짝짓기(`academy/references.py`)가 있다. 작품 중심이고 단원 번호는 모른다.
- 플레이어의 퀴즈 탭은 4지선다·빈칸만 푼다(`academy/static/common.js`의 `quizCard`, `watch.js`의 `renderQuiz`). 지문, OX, 단답형, 서술형은 없다.
- 서버는 `/api/videos/{id}`로 영상별 정보를 주고, 설정 파일(`~/.config/academy/academy.env`)로 경로를 받는다. `python -m academy.check`가 설정을 점검한다.
- 플레이어는 인터넷에도 열 수 있다(`ENTRY_SECRET`, `docs/인터넷-열기.md`). 이 경우 교재 지문이 학생 화면에 보인다.

## 접근 (둘 중 B로 정함)
- **A. 영상 아래에 PDF 링크만 붙이기**: 구현이 가장 작다. 하지만 학생이 종이에 풀어야 하고 자동 채점이 없다. PDF를 서버에서 따로 서빙해야 한다. "바로 풀 수 있게"라는 요구에 맞지 않아 버렸다.
- **B. 플레이어에 요점노트·시험대비 탭을 새로 만들기 (선택)**: 한 개의 JSON에서 PDF와 플레이어 화면을 모두 만든다. 요구에 맞고 PDF와 화면의 내용이 어긋나지 않는다. 화면 코드를 새로 짜야 한다.
- C. 기존 `references.json` 형식을 넓혀 쓰기: 형식이 작품·빈칸·어휘에 묶여 있어 지문·5지선다·OX·서술형을 담을 수 없다. 버렸다.

## 결정한 것
### 1. 데이터: 단원 하나당 JSON 항목 하나
새 파일 `STUDY_FILE`(JSON 목록). `references.json`은 그대로 둔다.
```
{"id": "midaen-4-2", "unit": "4-2",
 "unit_title": "주제 통합적 읽기(한 권 읽기) - 친구에 관한 세 가지 글",
 "works": ["벗들이 지어 준 나의 공부방", "참된 친구란 무엇일까요", "인공지능과 친구가 될 수 있을까"],
 "scope": ["미래엔"],
 "notes": {"unit": "...", "sub": "...", "goals": [...], "blocks": [...], "words": [...]},
 "quiz": {"passages": [{"label": "가", "title": "...", "paras": [...]}],
          "mc":    [{"q": "...", "choices": [5개], "answer": 0~4, "exp": "..."}],
          "sub":   [{"q": "...", "model": "...", "note": "..."}],
          "ox":    [{"q": "...", "answer": true, "exp": "..."}],
          "short": [{"q": "...", "answer": "...", "alts": ["..."], "exp": "..."}]}}
```
문항 수는 항상 객관식 10, 주관식 5, OX 10, 단답형 10이다.

**`notes.blocks` 형식** (PDF와 플레이어가 같은 형식을 쓴다):
```
{"t": "big",   "title": "...", "blocks": [ ...아래 블록들... ]}   # 큰 제목 아래 묶음
{"t": "h",     "title": "...", "sub": "..."}                      # 소제목(예: 글 1 제목, 출처)
{"t": "def",   "text": "..."}                                     # 뜻풀이 상자
{"t": "tip",   "text": "..."}                                     # 꼭 기억해요
{"t": "card",  "title": "...", "items": ["..."]}                  # 제목 있는 목록 카드
{"t": "list",  "items": ["..."]}                                  # 일반 목록
{"t": "flow",  "title": "...", "steps": [{"label": "...", "text": "..."}]}  # 단계 흐름
{"t": "table", "head": ["..."], "rows": [["..."]]}                # 표
```
- 글 안의 꾸밈은 `<b>`, `<u>`, `<br>`만 허용한다. 플레이어는 이 세 가지만 해석하는 안전한 변환기를 쓰고(허용하지 않은 태그는 글자로 보여 줌), 통째로 `innerHTML`에 넣지 않는다.
- 지문의 출처 줄은 문단에 섞지 않고 `passages[].source`로 따로 둔다.

**자료의 현재 위치**: 4-2·5-1의 요점노트와 시험 내용은 지금 이 대화 환경의 임시 폴더에 파이썬 사전(`content.py` 등)으로만 있고 저장소에는 없다. 이 사전들을 위 형식의 JSON으로 옮겨 `tools/study/data/`에 둔다. 드라이브의 PDF는 이 JSON에서 다시 만든 것과 내용이 같게 한다. 이 두 항목도 **초안**에서 시작하며, 선생님이 승인하기 전에는 학생에게 보이지 않는다.

### 2. 연결 규칙: 단원 번호·단원 제목·작품명을 모두 본다
영상의 **파일 이름**(마지막 경로 조각)과 **폴더 경로**를 따로 본다. 한글은 NFC로 합치고 띄어쓰기·기호는 무시한다.
- 규칙 1(단원 번호): 파일 이름이 `4-2` 같은 단원 번호**로 시작한다**(바로 뒤에 숫자가 이어지지 않음, 점·공백·밑줄은 허용). 이름 중간에 있는 `4-2`(날짜, 강의 순번 등)는 단원 번호로 보지 않는다. 번호만으로 연결된 영상은 확인 도구에서 ‘번호로만 연결’이라고 따로 표시해 선생님이 먼저 확인하게 한다.
- 규칙 2(단원 제목): 파일 이름에 `unit_title`(번호 뒤의 제목, 네 글자 이상)이 들어 있다.
- 규칙 3(작품명): 파일 이름에 `works` 중 하나가 들어 있다(세 글자 이상).
- 세 규칙 모두 **`scope`의 모든 낱말이 폴더 경로에 있어야** 연결한다(예: 폴더에 `미래엔`). `scope`가 비어 있으면 연결하지 않는다.
- 한 영상이 **서로 다른 단원 둘 이상**과 맞으면 연결하지 않고 '모호함'으로 알린다. 같은 단원의 여러 규칙에 걸리는 것은 문제없다.
- 선생님이 고치는 파일 `STUDY_LINKS_FILE`(선택): `{"영상 제목(경로 포함)": "항목 id"}`로 직접 연결하고, 값이 `null`이면 연결하지 않는다. 이 파일이 규칙보다 앞선다.
- 확인 도구: `python -m academy.study_links`가 영상 폴더를 훑어 '연결됨 / 연결 안 됨 / 모호함'을 목록으로 보여 준다. 영상 이름이 제각각이므로 이 목록으로 빠진 것을 `STUDY_LINKS_FILE`에 채운다.

### 3. 서버
- `STUDY_FILE`을 읽어 연결을 한 번 계산해 기억한다(`references`와 같은 방식).
- `/api/videos/{id}`에 `study: [{"id","title","hasNotes","hasQuiz"}]`만 넣고, 내용은 `/api/study/{id}`로 따로 준다(영상 상세가 커지지 않게). 기존 입장·접근 제한을 그대로 따른다.
- **인터넷 공개 기본값은 끈다**: 교재 지문 원문이 나가는 기능이므로, 학원 내부망이 아닌 곳(인터넷)에서 온 요청에는 `STUDY_INTERNET=1`을 설정했을 때만 `study` 필드와 `/api/study`를 준다. 설정하지 않으면 내부망에서만 보인다. 학원이 인터넷 접속을 쓴다면 선생님이 이 설정을 켜야 한다(그 경우 지문이 입장 링크를 가진 학생에게 보인다).
- `python -m academy.check`에 `STUDY_FILE` 경로·형식 점검을 더한다(문항 수, 보기 5개, 정답 번호 범위).

### 4. 플레이어(`watch.html`, `watch.js`, `common.js`, `style.css`)
- `study`가 있는 영상에만 탭 **요점노트**, **시험대비**를 보인다. 없으면 숨긴다.
- 요점노트: 설계 1의 `blocks`(표, 카드, 흐름, 꼭 기억해요, 목록, 낱말 풀이)를 그린다. 화면에서 읽기 좋게 하고 인쇄용 모양은 만들지 않는다.
- 시험대비: 위에 지문 [가][나][다]를 접어 둘 수 있는 상자로 두고, 아래에 문제를 풀게 한다.
  - 객관식(5지선다)과 OX: 기존 `quizCard`를 재사용한다. 고르면 바로 정답·해설.
  - 단답형: 입력 후 확인. 정규화한 값이 `answer`나 `alts`와 같으면 정답. 다르면 정답을 보여 주고 ‘내 답도 맞아요’로 학생이 고칠 수 있다.
  - 주관식: 쓰는 칸(저장 안 함) + ‘모범 답안 보기’ + ‘알았어요/몰랐어요’(기존 빈칸 카드와 같은 방식).
  - 점수는 이 영상의 객관식·OX·단답형 합으로 보여 주고 브라우저에만 저장한다. **기존 `wrong:`·`score:` 저장 칸은 쓰지 않는다**(기존 퀴즈 탭이 열릴 때 모르는 문제를 지우기 때문). 별도 칸 `study:`를 쓴다.
  - 공용 `quizCard`는 **고치되 기존 동작은 그대로** 둔다. 선택 인자(`{review: false}`)를 하나 받아, 켜면 ‘틀린 문제 복습에 넣었어요’ 문구와 복습 기록 호출을 빼고, 기본값은 지금과 같다. 시험대비 항목은 `{q, choices, answer, exp}`를 `{question, choices, answer, explanation}`으로 바꿔 넘기는 작은 변환 함수를 쓴다.

### 5. 만드는 순서와 검수
1. **먼저 4-2와 5-1만으로 처음부터 끝까지 한 번 완성한다**: JSON 변환 → 서버 → 플레이어 → 연결 규칙 → 점검 도구 → 시험.
2. 나머지 PDF는 한 단원씩: 드라이브에서 읽고 → 요점노트·문제 JSON 작성 → 형식 점검(문항 수·보기 5개·정답 번호) → 별도 대조 단계(원문을 다시 읽어 지문과 정답을 확인) → PDF 두 개 생성 → 드라이브 업로드.
3. 새로 만든 항목은 **`study_draft.json`에만** 모은다(저장소 `tools/study/data/`). 선생님이 드라이브 PDF를 검토해 승인한 항목 id를 알려 주면, `tools/study/promote.py 항목id…`가 그 항목만 서버용 `study.json`으로 모은다. 이 파일을 학원 서버의 `STUDY_FILE` 위치로 복사하는 것은 서버 담당자가 한다(이 환경에서는 학원 서버에 접근할 수 없다). 학생에게는 승인된 것만 보인다.
   - 요점노트·문제 JSON의 작성, 대조, PDF 생성, 드라이브 업로드는 이 환경에서 Claude가 한다.
4. PDF와 JSON을 만드는 도구(JSON→HTML→PDF)는 저장소 `tools/study/`에 둔다. 글꼴은 Noto Sans KR(npm `@fontsource/noto-sans-kr`)을 쓴다.

### 6. 시험
- `tests/`에 연결 규칙(번호·제목·작품명·범위·모호함·직접 연결·`null`) 시험, `/api/study` 시험, `check` 시험을 더한다. 실제 브라우저 시험은 기존 `tests/e2e` 방식을 따른다(브라우저 도구가 없으면 건너뜀).
- 시험에 쓰는 자료는 가짜 지문만 쓴다. 저장소에 교재 원문을 넣지 않는다.

## 알려진 위험
- **저작권·공개**: 시험지와 요점노트에 교재 지문 원문이 들어간다. 학원 내부용으로만 쓰고, 플레이어를 인터넷에 열어 두었다면(`ENTRY_SECRET`) 학생 화면에 원문이 나간다. 저장소에는 올리지 않는다(`STUDY_FILE`은 서버에만 둔다).
- **영상 폴더 구조를 모른다**: 폴더 이름에 `미래엔`이 들어 있는지 확인하지 못했다. 들어 있지 않으면 규칙이 아무것도 연결하지 못하고, '연결 안 됨' 목록과 `STUDY_LINKS_FILE`로 메꿔야 한다.
- **학년을 모른다**: PDF에서 확인하지 못했다. 같은 출판사 아래 다른 학년에도 같은 단원 번호가 있으면 잘못 붙을 수 있으므로, 학년을 알면 `scope`에 폴더의 학년 낱말(예: `중2`)을 함께 넣는다. 확인되기 전까지 `scope`에 학년이 없는 항목은 ‘번호로만 연결’ 표시와 함께 선생님이 먼저 확인한다.
- **영상 파일 이름 견본이 없다**: 단원 번호로 시작하지 않고 `3강 …`처럼 강의 순번으로 시작하는 이름이 많다면 규칙 1은 거의 쓰이지 않고 규칙 2·3과 `STUDY_LINKS_FILE`이 주된 길이 된다.
- **품질**: 문제는 AI가 만든다. 앞서 만든 시험지에서 지문 발췌가 원문과 어긋난 곳이 있었다. 그래서 대조 단계와 선생님 승인을 거친다.
- **드라이브 읽기 한계**: `4-1`(42MB)은 끝까지 읽히지 않을 수 있다. 그러면 그 파일만 나누어 올려 달라고 요청한다.
- **비용**: 단원 하나당 PDF 읽기와 작성, 대조로 토큰이 적지 않게 든다. 15개를 몇 개씩 나누어 돌린다.

## 빌더에게 맡기는 것
JSON 파일 이름과 환경 변수 이름의 세부, 탭 이름의 CSS 모양, 단답형 정규화의 세부 규칙(띄어쓰기·괄호·대소문자), `tools/study/`의 폴더 구성, `study_links` 출력 모양.
