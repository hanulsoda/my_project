# 판서 내용 분석 설계

- 날짜: 2026-10-19
- 상태: 대화에서 방식 A와 ①캡처·선택 ②학생 화면 ③변경·확인 방법 승인. 이 문서 검토 대기.

## 목표

칠판·태블릿에 쓴 수식과 정리를 요점 정리에 반영하고, 챕터마다 그때의 칠판 사진을 보여 줘서 학생이 판서 노트처럼 복습할 수 있게 한다.

## 정해진 사항 (사용자 답변)

- 보여 주기: 요점 정리 글에 판서 내용을 넣고, 챕터마다 칠판 사진 1장을 함께 보여 준다. AI 질문하기는 지금처럼 대본만 쓴다.
- 영상 형태: 칠판 고정 카메라, 태블릿·화면 필기, 자주 움직이는 카메라가 모두 있다.
- 방식 A: 일정 간격으로 캡처하고 거의 같은 장면은 버린다.

## 분석 단계

### 캡처 (`academy/frames.py`)

- 영상의 0초부터 **30초마다** 한 장을 PyAV로 읽는다(이미 설치된 라이브러리, ffmpeg 프로그램 불필요). 첫 화면 시각이 0이 아닌 파일도 영상 시작을 0초로 센다(플레이어·대본과 같게).
- 각 장면을 긴 쪽 **1280**(다른 쪽은 비율대로, 작은 영상은 키우지 않음)으로 줄이고, 휴대폰 영상의 회전 정보대로 세운 뒤 JPEG(품질 75)로 만든다. (사진이 20장을 넘으면 API가 한 변 2000px 넘는 사진을 거절하므로 세로 영상도 긴 쪽 기준.)
- **겹치는 장면 버리기:** 장면을 32×18 흑백으로 줄여 지금 장면의 첫 화면과 화소 차이의 평균을 비교하고, 0~255 기준 **8 미만**이면 같은 장면으로 본다. 같은 장면에서는 **마지막 화면**을 남긴다(판서가 가장 많이 채워진, 지우기 직전 칠판). (최종 검토에서 바뀜: 처음에는 첫 화면을 남겼는데, 그러면 판서를 쓰기 전 빈 칠판이 남았다.)
- **장수 제한:** 남은 장면이 `min(100, max(1, 올림(영상 길이 ÷ 60초)))`장보다 많으면 시간 순으로 고르게 골라 그 수로 줄인다. (1시간 강의 → 최대 60장, 아무리 길어도 100장. Claude API 한 요청의 이미지 한도 안.)
- 결과: `[(초, JPEG 바이트), ...]` 시간 순.
- 영상 트랙이 없으면 빈 목록, 읽다가 오류가 나면 그때까지 찍은 사진으로 경고를 출력하고 계속한다. 사진은 덤이라 이 때문에 영상 전체 분석이 실패하면 안 된다.

### 요점 정리 요청 (`academy/ai.py`)

- `make_study_guide(client, title, segments, frames=[])`
- 사용자 메시지는 [대본 텍스트] 다음에 장면마다 `[분:초] 화면` 텍스트 + 이미지 블록(base64 JPEG)을 시간 순으로 넣는다.
- 프롬프트에 추가: 화면의 판서(수식·도표·정리)를 읽어 요점에 반영하고, 수식은 텍스트로 옮겨 적는다. 챕터마다 판서가 가장 잘 보이는 화면의 시점을 `board`에 적고, 판서가 없으면 빈 문자열.
- JSON 스키마의 챕터에 `board`(문자열, "분:초" 또는 "") 추가.
- 반환되는 챕터의 `board`: 보낸 장면 중 그 시점과 **가장 가까운 장면의 초**(정수) 또는 `None`. 장면을 보내지 않았거나 빈 문자열이면 `None`.

### 일괄 분석 (`academy/analyze.py`)

- `analyze_all(video_dir, data_dir, transcribe, make_guide, extract_frames, force=False)`
- 요점 정리를 만들기 직전에 `extract_frames(path)`로 장면을 얻어 `make_guide(title, segments, frames)`에 넘긴다.
- 챕터가 고른 장면만 `data/frames/<영상 id>/<초>.jpg`로 저장한다(`library.save_frame`). 저장도 임시 파일 후 바꿔치기.
- 무음 영상은 지금처럼 Claude를 부르지 않고, 장면도 읽지 않는다.
- 이미 분석된 영상은 건너뛴다(지금과 같음). 사진을 넣으려면 `--force`로 다시 분석한다.

## 학생 화면

- 요점 정리의 챕터 카드에서, `board`가 있으면 핵심 내용 아래에 칠판 사진을 보여 준다.
  - `<button>` 안의 `<img loading="lazy" alt="판서 분:초">`, 누르면 그 시점으로 이동.
- 서버: `GET /frames/{video_id}/{name}`
  - `video_id`는 실제 영상이어야 하고(없으면 404), `name`은 `숫자.jpg`만 허용(아니면 404).
  - 파일이 없으면 404.
  - 입장 확인이 켜져 있으면 다른 화면처럼 통과 쿠키가 있어야 한다(기존 미들웨어가 그대로 적용).

## 비용 (추정)

이미지 1장(1280×720)은 약 1,200 토큰. 1시간 강의 60장 ≈ 7만 토큰 ≈ $0.3 (Claude Opus 5.5 입력 $4/100만 토큰). 영상마다 한 번.

## 테스트

- `frames.py`: PyAV로 시험 영상을 코드로 만든다(예: 3분, 0~60초 흰 화면, 60~120초 글씨 블록, 120~180초 다른 글씨 블록).
  - 30초 간격으로 읽고 같은 장면은 버려 3장만 남는다(0, 60, 120초).
  - 장수 제한: 가짜 장면 목록으로 고르게 줄이기를 확인.
  - 영상 트랙이 없는 파일 → 빈 목록.
- `ai.py`: 가짜 Claude로 이미지 블록 수·순서·형식 확인, `board` 시점이 가장 가까운 장면 초로 바뀌는지, 빈 문자열은 `None`.
- `analyze.py`: 가짜 함수로 고른 장면만 저장되는지, 무음 영상은 장면을 읽지 않는지.
- `server.py`: 사진 제공, 잘못된 이름·없는 영상 404, 입장 확인 켜짐에서 쿠키 없으면 401.
- 브라우저: 사진이 챕터에 보이고 누르면 이동. 기존 화면 검사 전부 통과.
- 확인 못 하는 것: 실제 판서를 얼마나 잘 읽는지(실제 강의 + API 키 필요).

## 범위 밖

- AI 질문하기에서 사진 사용, 챕터당 여러 장, 사진 크게 보기 창.
- 장면 전환 감지, 판서만 잘라내기, 손글씨 인식 별도 모델.
- 이미 분석된 영상에 사진만 추가하는 별도 명령.
