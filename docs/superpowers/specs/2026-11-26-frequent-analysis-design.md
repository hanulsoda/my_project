# 새 강의 분석을 낮에도 자주 돌리기 (짧은 설계)

## 왜 하는가
지금은 새 영상 분석이 매일 밤 23시에 한 번 돌아서, 낮에 올린 영상은 다음 날에야 학생이 볼 수 있다.
영상을 올린 뒤 **20~30분 안에** 학생이 볼 수 있게 하고, 사람이 분석을 챙기느라 시간을 쓰지 않게 한다.

## 목표 / 비목표 / 하면 안 되는 것
- 목표: 새 영상이 올라오면 사람 손 없이 20~30분 안에 분석을 시작한다.
- 비목표: 에이전트·상시 감시 프로그램을 새로 만들기, 요점 정리 검수 단계 추가(따로 다룰 일).
- 하면 안 되는 것(실패로 본다): 같은 영상을 두 번 분석함, Claude 비용이 늘어남, 분석 때문에 학생 접속이 느려짐.

## 접근 (둘 중 A로 정함)
- **A. 예약 주기만 바꾸기 (선택)**: 밤 23시 한 번 → 15분마다. 이미 있는 안전장치를 그대로 쓴다.
  동시 실행 잠금, NAS 복사 중(10분 이내 변경) 영상 미루기, 이미 분석한 영상 건너뛰기, 요점 정리 Claude 재질문 2번 제한.
- B. 새 파일을 지켜보는 상시 프로그램 (버림): NAS는 파일 변경 감지가 불안정해 결국 주기 확인이 되고, 코드만 늘어난다.

## 결정한 것
1. cron 예시를 `*/15 * * * *`로 바꾼다. (내 판단: 하루 종일. 학원 서버 부하가 문제면 시간대를 줄인다.)
2. 코드(`academy/analyze.py`)는 바꾸지 않는다. README의 cron 예시 설명만 고친다.
3. 적용 전에 영상이 새로 없을 때 한 번 돌리는 시간을 `time`으로 잰다(NAS 훑기·모델 로딩 비용).
   한 번이 몇 분 이상 걸리면 그때 다시 설계한다(15분 주기가 겹치거나 서버를 계속 붙잡을 수 있어서).

## 알려진 위험 (확인 필요)
- 매 실행마다 영상마다 "이미 분석됨" 줄이 로그에 쌓여 `new-videos.log`가 커진다. 하루 96번 돌면 크기가 문제인지 본다.
- 받아쓰기 자체가 계속 실패하는 영상은 15분마다 GPU로 다시 시도한다(Claude 비용은 들지 않는다). 현황 화면에서 실패가 반복되면 알아챈다.
- 현황 화면의 '새 강의 분석'이 날짜 줄을 그대로 보여 주는데, 줄이 하루 96개가 되어도 읽기 좋은지는 확인하지 않았다.

## 남은 것
- 이 환경은 학원 서버에 접근할 수 없다. 서버 crontab 적용과 시간 측정은 서버에서 하는 사람이 한다.
