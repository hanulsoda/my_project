# 학습 플레이어 DS918+ 배포 설계

- 날짜: 2026-10-18
- 상태: 대화에서 ①구성 ②입장 링크 ③변경·확인 방법 승인. 이 문서 검토 대기.

## 목표

학원 사이트에 로그인한 학생만 집에서도 학습 플레이어로 강의를 볼 수 있게, 플레이어를 시놀로지 DS918+에서 서비스한다.

## 정해진 사항 (사용자 답변)

- 학생은 외부 웹호스팅에 있는 학원 사이트(PHP로 가정)에 로그인해서 들어온다.
- 지금 강의 영상은 DS718+가 학원 도메인으로 제공한다. 앞으로 바깥 접속은 모두 DS918+가 맡고, DS718+는 바깥에 아무것도 제공하지 않는다.
- 영상 파일은 두 시놀로지 모두에 있을 것이다(사용자도 확실하지 않음 → 설치 안내에 비교·복사 단계를 넣는다).
- 분석(Whisper + Claude)은 Z840에서 하고 결과를 DS918+에 저장한다.
- 로그인한 학생만 들어오게 하는 방식은 "입장 링크"(아래).

## 구성

```
학생 브라우저
  │ 1. 학원 사이트에 로그인 → "강의 보기" 클릭 (서명된 입장 링크)
  ▼
https://study.<학원도메인>  ── 공유기 80/443 → DS918+
  │ DSM 역방향 프록시 + Let's Encrypt 인증서
  ▼
DS918+ Container Manager: 학습 플레이어 컨테이너 (웹 서버만, Whisper 없음)
  ├─ /videos  ← 영상 공유 폴더 (읽기 전용)
  └─ /data    ← 분석 결과 폴더
                 ▲
Z840: 두 폴더를 네트워크 드라이브(SMB)로 연결해 분석하고 /data에 바로 저장
```

- 웹 서버는 요청마다 폴더를 읽으므로, Z840이 결과를 저장하면 다시 시작하지 않아도 바로 보인다.
- 컨테이너에는 웹 서버에 필요한 패키지(anthropic, fastapi, uvicorn)만 넣는다. 이를 위해 `requirements-server.txt`를 나누고, 기존 `requirements.txt`는 그것을 포함한 뒤 분석·테스트 패키지를 더한다.
- 설치: 사용자가 GitHub에서 저장소 ZIP을 받아 NAS 폴더(예: `/volume1/docker/study-player`)에 풀고, Container Manager의 "프로젝트"로 `docker-compose.yml`을 열어 NAS에서 이미지를 만든다. 별도 이미지 저장소는 쓰지 않는다.

## 입장 링크

학원 사이트와 플레이어가 비밀 키(`ENTRY_SECRET`, 32자 이상) 하나를 나눠 가진다.

1. 학원 사이트(로그인한 화면)가 링크를 만든다.
   `https://study.<학원도메인>/enter?exp=<만료 유닉스 초>&sig=<서명>`
   - `exp` = 지금 + 300초(5분)
   - `sig` = HMAC-SHA256(키=비밀 키, 내용=`"enter:" + exp`)의 16진수 소문자
   - PHP: `hash_hmac('sha256', "enter:$exp", $secret)` — 함수 하나로 제공
2. 플레이어의 `/enter`가 서명과 만료를 확인한다.
   - 맞으면: 통과 쿠키를 주고 강의 목록(`/`)으로 보낸다.
   - 틀리거나 만료면: 아래 "막힘 화면".
3. 통과 쿠키 `study_pass` = `<만료>.<HMAC("pass:" + 만료)>`, 만료 = 지금 + 12시간.
   HttpOnly, SameSite=Lax. 요청이 https로 들어온 경우(역방향 프록시가 알려 줌) Secure도 붙인다.
4. `/enter`를 뺀 모든 경로는 유효한 통과 쿠키가 있어야 한다.
   - 경로가 `/api/` 또는 `/media/`로 시작하면: 401 (JSON 오류).
   - 그 밖의 모든 경로(화면·CSS·JS): 401과 함께 "학원 사이트에 로그인한 뒤 들어와 주세요" 안내 HTML(+ `SITE_URL`이 있으면 링크). 안내 화면은 파일을 따로 읽지 않는 한 장짜리 HTML이다.
- 서명 비교는 시간 차이로 새지 않게 `hmac.compare_digest`를 쓴다.
- 두 서버의 시계는 NTP로 맞춰져 있다고 가정한다(시놀로지·웹호스팅 기본값).
- 학생 아이디는 링크에 넣지 않는다. 지금 쓰는 곳이 없다.

### 비밀 키가 없을 때

- `ENTRY_SECRET`이 비어 있으면 입장 확인을 하지 않는다(지금처럼 열림). Z840·PC에서 시험할 때용.
- 시놀로지용 `docker-compose.yml`은 `REQUIRE_ENTRY=1`을 설정한다. 이때 비밀 키가 없거나 32자보다 짧으면 서버가 시작하지 않고 이유를 출력한다. 비밀 키를 빠뜨린 채 인터넷에 열리는 일을 막기 위해서다.

## 설정값 (환경 변수)

| 이름 | 설명 |
| --- | --- |
| `ENTRY_SECRET` | 입장 링크 비밀 키. 학원 사이트 PHP와 같은 값. |
| `REQUIRE_ENTRY` | `1`이면 비밀 키 없이는 시작하지 않음 (시놀로지용). |
| `SITE_URL` | 막힘 화면에 보여 줄 학원 사이트 주소 (선택). |
| 기존 `VIDEO_DIR`, `DATA_DIR`, `ANTHROPIC_API_KEY`, `CLAUDE_MODEL` | 그대로. 컨테이너에서는 `/videos`, `/data`. |

## 새 파일·바뀌는 파일

- `academy/server.py`: 입장 확인(`/enter`, 쿠키 검사), 시작 시 비밀 키 검사.
- `requirements-server.txt`(새), `requirements.txt`(앞의 것을 포함하도록).
- `Dockerfile`(새): python 3.12 slim, 서버 패키지만, `uvicorn --proxy-headers`.
- `docker-compose.yml`(새): 포트 8000, 폴더 연결, 환경 변수, 자동 재시작.
- `deploy/study_player_link.php`(새): 입장 링크를 만드는 PHP 함수.
- `docs/시놀로지-설치.md`(새): 클릭 순서대로 쓴 설치 안내.
  1. 두 시놀로지의 영상 폴더 비교·복사 (윈도우 `robocopy /L`로 빠진 파일 목록 → 복사)
  2. Container Manager 설치, 프로젝트 만들기, 비밀 키 넣기
  3. 역방향 프록시(`study.<학원도메인>` → `http://localhost:8000`)와 Let's Encrypt 인증서
  4. 학원 도메인 DNS에 `study` 추가, 공유기 80/443을 DS918+로 변경
  5. 학원 사이트에 PHP 함수와 "강의 보기" 버튼 추가
  6. Z840에서 두 폴더를 연결해 분석
- `README.md`: 시놀로지 설치 안내 링크.

## 테스트

- pytest:
  - 맞는 링크 → 통과 쿠키 + 목록으로 이동
  - 틀린 서명, 만료된 링크, 값이 빠진 링크 → 막힘
  - 쿠키 없음, 위조 쿠키, 만료 쿠키 → 화면 401 안내, API·영상 401
  - 비밀 키 없음 → 지금처럼 열림
  - `REQUIRE_ENTRY=1`인데 비밀 키 없음·짧음 → 시작 거부
- PHP 함수가 만든 링크를 플레이어가 통과시키는지: 이 환경에 PHP가 있으면 실제로 실행해 확인하고, 없으면 같은 HMAC 계산임을 문서로 밝힌다.
- Docker: 이 환경에서 이미지를 실제로 만들고 띄워, 입장 링크로 들어가 영상이 재생되는지 브라우저로 확인한다(가능한 경우).
- 기존 테스트 전체와 화면 검사도 그대로 통과해야 한다.

## 범위 밖

- 실제 시놀로지·공유기·DNS·학원 사이트 적용 (안내 문서로 대신함).
- 학생별 기록(메모·진도 서버 저장), 학생 아이디 전달.
- 판서 분석, GPU 2개 동시 사용, 실제 영상 품질 조정 (별도 작업).

## 사용자 확인이 필요한 것 (설치할 때)

- 학원 사이트가 PHP인지 (아니면 그 언어로 함수 제공).
- 쓸 주소(`study.<학원도메인>`)와 DS918+의 영상 공유 폴더 경로.
- DS718+로 연결된 기존 영상 주소를 학원 사이트에서 새 "강의 보기"로 바꾸는 일.
